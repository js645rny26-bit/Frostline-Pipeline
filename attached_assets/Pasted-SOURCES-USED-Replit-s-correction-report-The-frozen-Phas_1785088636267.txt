One remaining provenance defect

This is not genuine cached-payload reuse:

readdir() finds an earlier JSON file, so emit “cached-payload reuse”

That proves only that the same game was fetched previously. It does not prove the current run loaded or reused cached data.

A second live fetch with another immutable payload is a repeat fetch, not cache reuse. Calling it cache reuse would create the same kind of misleading provenance #63 was designed to eliminate.

Required correction

Use these semantics:

Prior timestamped payload exists + fresh network fetch succeeds
→ REPEAT_FETCH_DETECTED or PRIOR_FETCH_EXISTS
Current request fails or is skipped and an earlier payload is actually loaded
→ CACHED_PAYLOAD_REUSED

If no cache-loading path exists, CACHED_PAYLOAD_REUSED should never be emitted. Its count remains zero until that behavior genuinely exists.

The one pre-existing unit-test failure does not block this bounded Phase 2 change because Replit reproduced it against the untouched baseline. It must remain disclosed, not called newly passing.
