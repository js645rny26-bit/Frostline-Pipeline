Important structural defects

1. The new commissioning sheets are absent

I found no sheets or workbook references for:

* SHADOW_VALIDATION
* REPLAY_RESULTS
* REPLAY_METRICS
* SHADOW_HISTORY
* SHADOW_OUTCOMES
* REGRESSION_REPORT
* STARTER_AUDIT
* VEHICLE_LOG
* VEHICLE_POSTMORTEM

That means this linked workbook does not currently contain the recently reported Modules 12s–17 outputs.

Most likely explanations:

* Replit is writing those sheets to a different workbook ID.
* The linked sheet is an older operational workbook.
* The latest changes were made after this export’s modification time but never published here.

This is the biggest finding.

2. SLATE_BOARD is header-shifted

The row values do not align semantically with the headers.

For example, a CHC–PIT row appears as:

Header	Stored value
Decision	OVER
Confidence	CORE
Expected_ROI	0.82
Recommendation	0.168
Notes	STRONG_BUY
Unnamed next column	blocker/null

So the actual row contract appears to be closer to:

Direction
Final_Decision
Confidence
Expected_ROI
Recommendation
Core_Blocker

but the displayed headers are offset or outdated.

This is not merely cosmetic. Any downstream reader relying on header names could interpret:

* CORE as confidence
* confidence as ROI
* ROI as recommendation
* recommendation as notes

That needs a schema repair.

3. DAILY_MATCHUPS contains undeclared appended columns

The defined headers end at Notes, but the sheet continues through column AU with many columns exported as:

* Unnamed: 25
* Unnamed: 26
* …
* Unnamed: 46

Those unnamed fields contain meaningful data such as:

* prior-start date
* innings
* pitch count
* days rest
* outing classification
* pitcher metrics
* market values

The data exists, but the header row was not expanded when those fields were appended.

This creates two risks:

1. Consumers cannot safely map the fields.
2. Later schema expansion can overwrite or misalign them.

4. Duplicate header in GAME_SUMMARY

Combined_Run_Multiplier appears twice:

* once in the earlier context block
* again near the park/weather audit fields

The values match, so this is not currently corrupting projections, but duplicate headers are unsafe for JSON conversion, CSV import, dataframe processing, and lookup-by-column-name logic.

One should be renamed or removed, likely:

Environment_Run_Multiplier

and

Combined_Run_Multiplier

or keep only the final audit field.

5. The schema reference is behind production

SCHEMA_REFERENCE documents the older core sheets, but it does not appear to include the newly added shadow, replay, regression, starter-audit, or vehicle-postmortem structures.

Even before those missing sheets are resolved, the live schema has drifted beyond its declared documentation.

6. The workbook is output-driven, not formula-driven

I found no worksheet formulas in the inspected engine ranges. The data is being computed by the external TypeScript pipeline and written as values.

That is acceptable architecture, but it means:

The workbook itself is not the calculation engine; it is the pipeline’s operational datastore and presentation surface.

Therefore, workbook inspection alone cannot prove the implementation logic. It can verify that outputs, schemas, and joins landed correctly.
