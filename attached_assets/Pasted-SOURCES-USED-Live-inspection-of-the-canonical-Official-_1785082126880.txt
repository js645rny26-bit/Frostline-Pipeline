Task #58 - Statcast Game Preview Pipeline Integration

Objective

Determine whether official Statcast game preview data can be reliably obtained, parsed, audited, and incorporated into the Frostline daily pipeline.

Do not assume that a stable public endpoint exists. Begin with a feasibility investigation. Do not change projections or CORE authorization until preview ingestion has passed structural validation, smoke testing, historical replay where possible, and live shadow validation.

Current confirmed state

The canonical workbook currently contains:

DAILY_MATCHUPS.Statcast_Last_Updated

However, there is no auditable evidence that actual Statcast game preview content is being fetched or used.

Current gaps:

* No preview-specific pipeline module status
* No preview availability or failure status by game
* No structured preview fields in the workbook
* No raw-payload provenance or checksum
* No indication of which preview fields affected projections
* No preview-specific counts in RUN_LOG
* No confirmation that Statcast_Last_Updated represents a successful preview fetch
* FanGraphs_Last_Updated and Statcast_Last_Updated currently share identical timestamps, which may indicate generic refresh stamping rather than independent source ingestion

Phase 0 - Feasibility investigation

Before writing production integration code, identify whether an authoritative and operationally stable source exists.

Source priority

Use this order:

1. Official MLB or Baseball Savant machine-readable JSON/API
2. Official MLB page data embedded in page source or client-side JSON
3. A documented and stable official feed accessible without authentication
4. HTML parsing only if the page is stable, server-accessible, and legally/operationally appropriate

Do not:

* fabricate an endpoint
* use postgame data as pregame preview data
* bypass authentication or anti-bot controls
* use an unofficial mirror without explicitly reporting it
* silently substitute another source and continue labeling it Statcast
* treat a page timestamp as proof that preview content was parsed

Required feasibility output

Return a report containing:

Source URL or endpoint pattern
Source owner
Request method
Authentication requirement
Example game identifier
Example response or payload structure
Whether historical dates are available
Whether the source works before first pitch
Whether doubleheaders are distinguishable
Whether starting-pitcher changes are reflected
Whether lineups are included
Rate-limit or blocking behavior
Expected failure modes
Operational recommendation:
  FEASIBLE
  FEASIBLE_WITH_LIMITATIONS
  NOT_RELIABLY_FEASIBLE

Capture sample payloads for at least three different games, including one ordinary game and one edge case such as a doubleheader, reschedule, opener, or changed probable pitcher.

Stop condition

If no reliable source can be found, stop after the feasibility report.

Do not build a browser scraper merely to satisfy the task.
